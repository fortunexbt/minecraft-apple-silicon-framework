    Let your agent help

    Give this prompt to Codex, Claude Code, or your preferred coding agent. It starts with your launcher, mods and image-quality preferences.

    Use https://github.com/fortunexbt/minecraft-apple-silicon-framework and follow silicon_shader/skills/silicon-shader/SKILL.md. Detect my Mac, launcher, existing Minecraft session, loader, mods, harness, image quality and compatible community recipes. Preserve my worlds, current settings and any game already in use; adapt one compatible setup in an isolated copy, keeping current image quality as the default floor.

For automatic performance comparison, require a supported game-control harness and the pinned disposable world. Run one matched baseline and one candidate on the same seed and fixed flight path; no manual steering or substitute terrain. Use brief in-game phase messages before measurement and after each capture. Announce the upcoming flight during warm-up; keep timed frames free of new chat messages or screenshots. Explain the candidate switch and final portrait outside measurement. Keep the repeat comparison under five minutes. If the world or supported controls are unavailable, finish setup and report performance as unmeasured instead of interrupting a running game.

After testing, take exactly one candidate screenshot from the shared front-facing view. Prepare a data-only submission with observed hardware, launcher/mods, agent/model/harness, recipe, screenshot and validated timing. Publishing is optional: publish only when this task already authorizes it; once authorized, do not ask again. Otherwise leave the validated draft local. Changes to code or toolkit still go through review.

    Public comparisons use the pinned standard workload shown by silicon-shader challenge workload. A compatible harness and save may take time to prepare. No performance result is assumed until the route receipt validates.

    Prefer the manual CLI?

    Requires Python 3.10+ and Minecraft Java. Use a Python environment to avoid changing your system packages.

    git clone https://github.com/fortunexbt/minecraft-apple-silicon-framework.git
cd minecraft-apple-silicon-framework
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .

    Check the recipe first

    FPS depends on the Mac, shader, scene, resolution and settings. Read the recipe and evidence before comparing two setups.

    1. Filter by your chip family, tier and memory.
    2. Standard-route setups share the pinned test scene and movement. Compare output and internal resolution, shader settings, view distance and hardware too.
    3. Ask your agent to check compatibility and prepare an isolated copy before trying a change.

    Each bar is a short CPU frame production measurement, not displayed or generated FPS. The notch on a bar is the matched baseline run from the same session. Run-to-run noise is about 1 to 3 FPS, so treat gaps under about 5 FPS between setups as ties.

    Earlier-route setups remain available as recipe ideas. Their FPS cannot be compared directly with the standard route. Captures are contributor-submitted, and an image-quality review is not an independent performance reproduction.
