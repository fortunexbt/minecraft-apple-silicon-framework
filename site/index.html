Let your agent help.

Give this prompt to Codex, Claude Code, or your preferred coding agent. It starts with your launcher, mods and image-quality preferences.

Find and try a Minecraft shader setup that would improve my experience on this Mac using https://github.com/fortunexbt/minecraft-apple-silicon-framework. Follow silicon_shader/skills/silicon-shader/SKILL.md. Detect my hardware and existing game, then compare compatible community recipes and screenshots. Adapt a recipe in an isolated copy while preserving my worlds and current settings. Use my current image quality as the default floor. If recording or submitting a performance comparison, first run `silicon-shader challenge workload` and follow its pinned world, route, movement and capture instructions for both baseline and candidate; never use a flat or different route as comparable evidence. Finish setup or tuning without a benchmark when no compatible harness is available. Ask only for missing choices or required access, and before publishing anything.

Public comparisons use the pinned standard workload shown by silicon-shader challenge workload. A compatible harness and save may take time to prepare; no performance result is assumed until the route receipt validates.

Prefer the manual CLI?

Requires Python 3.10+ and Minecraft Java. Use a Python environment to avoid changing your system packages.

git clone https://github.com/fortunexbt/minecraft-apple-silicon-framework.git
cd minecraft-apple-silicon-framework
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .

A QUICK WAY TO USE THE LIBRARY

Check the recipe first.

FPS depends on the Mac, shader, scene, resolution and settings. Read the recipe and evidence before comparing two cards.

  1. Filter by your chip family, tier and memory.
  2. Standard-route cards share the pinned test scene and movement. Compare output and internal resolution, shader settings, view distance and hardware too.
  3. Ask your agent to check compatibility and prepare an isolated copy before trying a change.

Earlier-route setups remain available as recipe ideas; their FPS cannot be compared directly with the standard route. Captures are contributor-submitted, and an image-quality review is not an independent performance reproduction.
